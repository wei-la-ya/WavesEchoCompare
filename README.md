# WavesEchoCompare

鸣潮声骸截图对比插件，依赖 [XutheringWavesUID](https://github.com/Loping151/XutheringWavesUID)（需先行安装）。

## 用法

发送声骸截图，并附命令（同一条消息）：

```
ww<角色名>提升预估          例: ww长离提升预估 (cost 由截图识别)
ww<角色名>提升预估<cost>    例: ww长离提升预估3
```

支持同一条消息发送多张图片，也支持一张图内横向或纵向排列的多张声骸卡，合计最多 5 个声骸。
例如发送 `ww长离提升预估`，同时附上一个 COST 4、两个 COST 3 声骸的截图。
不同 COST 混合时不带命令末尾的 cost；带 cost 时，会对本条消息中的全部声骸统一指定 COST。
截图中每张声骸都应包含双主词条与副词条。某张解析失败会指出图片及卡片序号，整批停止。
副词条不足五条时会明确标记数量，请核对是否尚未调谐或存在漏识别。

COST 判断顺序：命令手动指定 → 截图中清晰的 COST 标识 → 主词条推断。
截图没有 COST 标识、标识识别置信度低或结果冲突时，会根据主词条类型与满级数值判断，
并用第二条固定主词条辅助校验。仍无法明确判断时，提示发送清晰截图或在命令中指定 cost。
目前仅支持满级（25 级）声骸详情截图。

| COST | 第一主词条（随机） | 第二主词条（固定） |
| --- | --- | --- |
| 1 | 攻击 18%、生命 22.8%、防御 18% | 生命 2280 |
| 3 | 攻击／生命／属性伤害加成 30%、防御 38%、共鸣效率 32% | 攻击 100 |
| 4 | 攻击／生命 33%、防御 41.8%、暴击 22%、暴击伤害 44%、治疗效果加成 26.4% | 攻击 150 |

主词条推断使用第一主词条的类型和满级数值，第二主词条用于校验和消歧。
副词条中的共鸣技能、共鸣解放、普攻、重击伤害加成分别保留原类型，不参与 COST 判断。

> 注意: `ww长离提升`（不带「预估」）是 XutheringWavesUID 的优化建议命令, 不属于本插件。

## 功能

1. 识别截图声骸的 cost、主词条、副词条（本地 OCR, 双 pass 抗模糊）。
2. 取当前绑定 UID 内对应角色面板, 替换对应 cost 槽位声骸词条。
3. 按实际面板的同 COST 槽位联合择优：每只新声骸只用一次，每个槽位最多替换一次。
   多个 COST 3／COST 1 同时替换时比较完整组合；若全部降低伤害，选择最终伤害最高、降幅最小的方案。
   提供的同 COST 声骸数量超过现有槽位时会报错，不会擅自丢弃或覆盖另一只新声骸。
4. 对比替换前后「全部伤害类型求和」, 回复: `伤害提升了约 X.X%` / `伤害降低了约 X.X%`。
5. 回复附带左右拼接面板图 (左: 替换前 / 右: 替换后)。
6. 回复列出每只声骸的图片来源和最终槽位。只在面板副本中模拟，沿用目标槽位的原声骸本体及套装。

## 性能

- 多图共用 HTTP 连接池，每次最多并发下载、处理三张图片。
- 保留最近 16 张图片的下载缓存，相同 URL 再次使用时不重复下载。
- 先按卡片分区，再合并文本；清晰卡首轮通过后不再运行放大 OCR，补救只处理不完整卡片。
- RapidOCR 共用单个实例并串行推理，避免线程安全问题和模型重复占用内存。
- 原面板只计算一次，与候选组合共用最多四个计算线程，不阻塞消息事件循环。
- 候选仅计算伤害，最后只渲染原面板和胜出面板，并行出图；胜出方案不再重复计算伤害。

## 依赖安装

插件 `pyproject.toml` 声明了 `rapidocr-onnxruntime`, gsuid_core 启动时自动安装
(需开启 `AutoInstallDep` 配置)。也可手动安装:

```
uv pip install rapidocr-onnxruntime
```
